# 誘餌頻道
> 指令：`/honeypot`  
> 權限需求：`管理伺服器 Manage Server`

用來抓洗版機器人：把一個（或多個）頻道設為誘餌，只要**任何人及機器人**在裡面發一句話，就視為洗版機器人或誤加入的自動化帳號。

## 指令

* `/honeypot add <channel>`：把頻道設為誘餌
* `/honeypot remove <channel>`：移除誘餌頻道
* `/honeypot list`：列出目前的誘餌頻道
* `/honeypot config [action] [delete_message] [timeout_minutes] [notify_owner]`：設定偵測到之後怎麼處理
* `/honeypot status`：查看目前設定
* `/honeypot check`：檢查機器人是否擁有權限執行操作

## 偵測到發言時會發生什麼事

**所有使用者（除了擁有者）**：將會依照 `/honeypot config` 的設定執行操作 `action`（預設**自動踢出**），視設定刪除該則訊息及設定私訊擁有者處理結果。

!!! tip "群組擁有者可以安全地自己測試"
    當機器人可以正常讀到頻道後，擁有者自行於頻道中輸入，訊息將會給予 ✅ 反應，不會刪訊息、不會嘗試處理、也不會私訊通知。  
    這是因為 Discord 平台本身不允許任何人（包含機器人）對擁有者執行踢出、禁言、封鎖等管理操作，強行嘗試只會出錯。  
    {==這個設計是刻意的==}，用於讓擁有者可以直接進誘餌頻道打一句話測試「機器人是否正常運作」，用來確認設定生不生效，不用擔心誤傷自己。

## 自動踢出前會先私訊當事人

當 `action` 設成「自動踢出」時，機器人會在踢出之前先私訊當事人，說明帳號在誘餌頻道發言、已被移出伺服器，並提醒「如果不是本人操作，帳號可能已被盜用」，建議改密碼、開兩步驟驗證、檢查已授權的第三方應用程式。這是因為誘餌頻道除了抓到真的洗版機器人，也可能抓到帳號被盜、被植入自動發訊外掛的真實使用者，直接默默踢掉不太公平。私訊送不出去（對方關閉私訊、封鎖機器人等）就直接放棄，不會卡住踢出動作本身。

??? note "為什麼預設是自動踢出"
    跟洗版偵測不同，誘餌頻道的用意是需要手動透過 `/honeypot add` 設定過才會生效，本來就是刻意設下的陷阱，一般人或一般訊息不會出現在裡面，誤傷機率低很多。但如果還是想更保守，可以用 `/honeypot config action:不處理` 不做其他處理。

??? note "為什麼不排除機器人帳號"
    洗版偵測跟黑名單偵測都會忽略機器人訊息，但誘餌頻道刻意**不**排除，因為洗版機器人本身就是機器人帳號，排除的話誘餌頻道永遠不會觸發。

## 權限與身分組位階檢查

當您發現機器人似乎無法正常運作（無法正常管理使用者）時，請使用 `/honeypot check` 進行檢查，該回覆下面會有一顆「🔄 重新邀請機器人」連結按鈕。  
如果檢查發現權限不夠，檢查指令的回覆下面會有一顆「🔄 重新邀請機器人」按鈕，點下去會重新走一次 Discord 應用程式加入伺服器的流程，完成後會直接補齊機器人所有需要的權限，這樣就可以不用把機器人踢掉重邀一次。  
但身分組位階這件事按鈕解決不了，還是要手動去 **伺服器設定 → 身分組** 調整順序。
